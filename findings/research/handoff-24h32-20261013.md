The shipping kernel collection keeps the C++ and C symbols for these kexts (4877 in X6000,
11923 in HWLibs), e.g. `_ipconfig_get_ip_discovery_info`, `_psp_cgs_read_register`,
`__ZN26AMDRadeonX6000_AMDHardware8powerOffEv`. The framebuffer's embedded display-core
code (`dc_*`, dmub, `program_pix_clk`) has no symbols. RaphaelGPU.cpp still addresses
about 106 `kOff*` constants plus ~75 literal offsets relative to the 24G830 images.

User goal (2026-10-12): the driver must work on every macOS 15 build and its updates
without per-build edits, and fail safe (no patching, no panic) when it cannot locate what
it needs; then a separate Tahoe (macOS 26) install that tracks its own updates. Userspace
patches pinned by image UUID (Metal driver, AppleGVA VCN DPM) need the same treatment.

## Other open work on branch candidate-484 (built, not hardware-tested)

- QEMU (pins v16, image `rgpu-qemu:c484-igpu-display`, `patches/qemu/10.1.2-gtk-usb-menu.patch`):
  Machine > USB Devices… writes `run/usb-picker.request`; the launcher's path unit opens
  `tools/rgpu-usb-picker.sh`. USB nodes are root-only on this host, so
  `/usr/local/libexec/rgpu-usb-grant` (installed by the user, polkit
  `AUTH_ADMIN_KEEP`) sets a per-device ACL; mounted disks and hubs are refused.
- Clipboard: the macOS virtio console driver stalls after two messages each way with
  `VIRTIO_RING_F_EVENT_IDX` (queue counters: no RX refill, TX stuck), and QEMU's vdagent
  never retries. 484 sets `event_idx=off` on the iGPU console's virtio-serial. The guest
  helper must also be started outside the old console launcher (it exits in iGPU mode).
- iCloud: macOS 15 rejected Apple ID because `kern.hv_vmm_present=1` (AuthKit -7066,
  Anisette -8008, AVPIdentity errors). `src/HideVmm.cpp` (user-authorized) answers 0 to
  user processes; on 24H32 in the plain VM the sysctl reads 0 and those errors stopped.
  Sign-in itself is untested. Clearing the CPUID hypervisor bit instead hangs OpenCore.
- `HIDE_VMM` in tools/macos-vm.sh defaults off.
