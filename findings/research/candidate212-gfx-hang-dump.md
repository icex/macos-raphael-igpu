## Why the kext could not read the IB

`CP_IB1_BASE` is a VMID 3 address. `GCVM_CONTEXT3_CNTL=0x3b` (depth 1, block size 7) and its
root `0x85b01e000` is 0x1b01e000 bytes above the physical framebuffer base `0x840000000`, past
the 256 MiB CPU-visible BAR, so no BAR0 read can walk it. Apple's report reads the IB through
`AMDRadeonX6000_IAMDHWChannel::mapCmdBuffers` (`IOAccelSysMemory::lockForCPUAccess`), which is
the path candidate 213 uses to print the whole buffer.
