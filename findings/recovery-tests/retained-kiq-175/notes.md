# Candidate 175 retained host-KIQ observation

This archive preserves the first bounded BAR0-only observation of candidate 175's retained host-KIQ scratch after its incomplete normal recovery. The immutable observation used boot `5d6f45d0-4384-4340-b819-7751bc26ebb3`, run `1a065e4f5f674cc0a26d4e9dbdf59649`, and recovery `e503b2ca63db4e11a21494d1841dca24`. `result.json` and `attempt.json` are byte-identical copies of the create-once files under `/home/bogdan/macos-vm/run/retained-kiq-inspections/`.

The observer mapped only BAR0 with read-only userspace protection and exposed no mutation method. Both capture passes were stable. The complete 64 KiB ring matched the exact source-built image. Its embedded sequence was decimal `1719349093` (`0x667b2f65`), and the current fence matched that value. The current RPTR report and stored WPTR were both `0x100`.

The 2 KiB MQD differed from the source-built initial image in exactly 14 bytes across six dwords; the other 506 dwords matched. The differences were the query-time low/high pair at byte offsets `0x158/0x15c`, connect-end-time low/high at `0x168/0x16c`, and connect-end PQ RPTR/WPTR at `0x174/0x178`. The reconstructed timestamps are `0x10612fbe02c` and `0x10612fbe020`, a difference of 12, while both final pointers are `0x100`. These changes are strongly consistent with CP or hardware lifecycle writeback, but the exact write trigger remains unresolved. [mqd-diff.md](mqd-diff.md) preserves the raw comparison and field provenance.

PCI command stayed `3`, reset methods stayed empty, no VM was active, and the postflight journal contained no new message or fault. Opening the VFIO device still entails kernel VFIO lifecycle configuration, so this is a read-only userspace observation rather than proof that device configuration was untouched. The observation has `authorizes_launch=false`, `authorizes_recovery=false`, and `authorizes_cleanup=false`; it cannot replace the failed schema-5 retirement receipt or authorize another launch. It also says nothing about Metal execution, which remains unproven.

The positive fence read does not show that candidate 175's earlier recovery poll would have seen the value. The observer read the 64 KiB ring, 2 KiB MQD, pointer block, and 4 KiB EOP block before its four-byte fence read; those intervening reads could have displaced or refreshed HDP cache lines. Candidate 175 causation therefore remains unresolved.

The source-backed correctness requirement is independent of that causal question. Linux v6.12 [`amdgpu_device_aper_access`](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/amdgpu/amdgpu_device.c) invalidates HDP and executes `mb()` before reading the PCI aperture. [`amdgpu_discovery.c`](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/amdgpu/amdgpu_discovery.c) selects `hdp_v5_0_funcs` for HDP 5.2.0; [`hdp_v5_0_invalidate_hdp`](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/amdgpu/hdp_v5_0.c) writes the invalidate trigger, and current upstream adds a same-register posting read. [`vfio_pci_core_mmap`](https://github.com/torvalds/linux/blob/v6.12/drivers/vfio/pci/vfio_pci_core.c) maps the PCI BAR noncached but performs no AMD HDP operation. [`gmc_v10_0_mc_init`](https://github.com/torvalds/linux/blob/v6.12/drivers/gpu/drm/amd/amdgpu/gmc_v10_0.c) shows why Linux's bare-metal x86 APU exception differs: it replaces the PCI aperture base with the physical framebuffer offset outside passthrough, while this VFIO mapping remains PCI BAR0.

The missing invalidate path is corrected offline in the frozen recovery helper: native aligned write-one to the discovery-derived BAR5 offset `0x3fc4`, same-register posting read, all-ones rejection, and an ordinary-memory full fence before the BAR0 completion reads. The complete offline Python suite passed 247/247 tests; [full-python-tests.log](full-python-tests.log) records the run. This change has not been hardware-qualified. [hdp-read-coherency-report.md](hdp-read-coherency-report.md) contains the complete source and ordering analysis.
